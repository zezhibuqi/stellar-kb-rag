# 增强模式检索改为双通道（BM25 关键词 + 向量）并引入 RRF 融合与双预算池

**背景（实测）**：探针显示，年报第 26 行的"21万吨…同比增长超六成"与第 136 行的释义表，在纯向量召回的 top-30 里分别是「完全不存在」与「排第 8 但被重排挤掉」；把召回 k 从 10 提到 30、候选数 3 提到 5、重排保留数 9 提到 12 均无效。结论：**字面精确目标需要一条字面检索通道**，调参治不了候选生成层的缺口。

**决策**：增强模式的检索改为两条通道——BM25 关键词通道（SQLite FTS5 + trigram 分词器）与既有向量通道。两路分别取 80 / 50 条后按 RRF 融合（k=60，只用名次、不比较两路分值），融合后截 30 送重排、重排保留 12、工具返回 5。

查询词构造：按标点/空格/数字/单位/英文切分；中文片段 ≤6 字整段作短语词，超过 6 字先整段、零命中再用头/中/尾片段补充；所有词包成双引号并翻倍内部引号。

**关键词席位保护按「最稀有命中词优先」**：融合 + 重排之后为关键词字面命中保留 2 个席位（`AGENT_KEYWORD_RESERVED`），因为释义表这类块语义分低、会被重排整体淘汰，而它是「正式全称」类目标的唯一依据。取席位时按命中词从最稀有到最常见排序后取前几组——按列表顺序取会先取到「年报」这类高频词的命中，等于没有保留。

**MATCH 与 LIKE 是降级关系，不是并行，且降级按词判定**：长度 <3 的词直接走 LIKE；长于 3 字的中文片段仍会派生 2 字头/尾词走 LIKE（「年报释义」在语料里不存在，但「释义」在），因此不能用「整条查询是否命中」来决定是否降级——否则「SC-300」命中就会掩盖「释义」无法字面匹配的事实。LIKE 自带 20 条独立配额，既不占用也不补充关键词通道的 80 条（不参与 RRF）。

**权限**：FTS 行携带 domain，走与向量通道同一套「角色 → 允许领域」过滤；LIKE 路径同样过滤——它是绕过 Chroma 的第二条路，漏掉即越权。

**索引生命周期**：表结构随 `init_db()` 创建；数据由灌库钩子增量维护、`keyword_index.backfill()` 按 `keyword_indexed_at IS NULL` 回填存量（幂等、可重复跑）、删除文档时按 doc_id 清理；索引写入失败不阻塞灌库，但通过 `documents.keyword_indexed_at` 留痕并在健康检查中暴露未入索引的文档数。

**证据单元折叠是双通道之外的第二号根因**：年报转换后没有 Markdown 标题，510 个切块全部落在同一个「章节」证据单元里，按 `(doc_id, parent_start_line, parent_end_line)` 去重会把整篇文档折叠成一条候选，同一文档里其余相关块永远进不了上下文。修复放在检索期：证据单元跨度超过 200 行时，去重键退化为切块粒度（`(doc_id, "chunk", chunk_id)`），同一文档内的多个不同块可以同时入选；表与小章节不受影响，原有去重意图保留。这是**权宜之计**——根治要在切片器层面收窄过大章节，代价是重灌（重新消耗 embedding 额度），本次刻意避开。

**第二轮证据分为两个独立预算池**：链式池与缺口补充池。链式池额度**按需求动态计算**（每子问题配额 × 链式子问题数），`AGENT_CHAIN_EVIDENCE_BUDGET`（15）是安全阀而非固定额度——规划器拆出的子问题数量本身可变，固定池必然在某些轮次饿死排在后面的链式义务；缺口补充池固定 4，因为它是机会性补查。去重集合全局共享（分的是预算不是去重范围），链式池先跑（义务优先，且可能顺带补上缺口），池未用满不借用、余量写入 trace。

**trace 支持变体级归因**：每个子问题下记录 `retrieval.variants[]`（变体类型、查询串、各通道命中数与最佳名次、融合后最佳名次、最终注入条数、是否走 LIKE），顶层记录两个池的用量与限额。

**Considered Options**：只调参数（k / 候选数 / 重排保留）——实测无效，目标块压根不在候选集；用 Chroma 的 `where_document` 子串过滤替代 BM25——需要先有"关键词"，且只能做"限定后按向量排序"，没有 BM25 排序；jieba 等中文分词 + BM25——需新依赖与词表维护，而 trigram 免词典、已验证三字以上可命中（代价是两字以下需 LIKE 兜底）；把关键词通道也接入标准模式与评测主线——会动到已稳定的主链路，先只在增强模式启用、评测加开关按需对照；第二轮沿用单预算池——链式义务会被机会主义的补查抢占，额度不可预测；在切片器层面收窄过大章节、让证据单元天然不折叠——根治，但必须整库重灌并重新消耗 embedding 额度，本次以检索期去重退化替代；链式池用固定额度——实现更简单，但规划器多拆一个子问题就会让排在后面的链式义务拿不到证据。

**Consequences**：需要一次本地回填（从 `source_content` 重建切块文本，**不调用 embedding、不需要重灌向量**）；中文两字及以下的词依赖 LIKE 全表扫描，在 671 块规模下可接受，文档量级上去后需重新评估（届时可换分词器或引入词典）；增强模式单次问答的检索开销上升（双通道 + 更宽候选），重排成本由"融合后截 30"约束；检索质量从此可按通道与变体归因，评测需新增"纯向量 vs 混合"对照开关；200 行阈值、席位保留数与两个池的额度都是启发式（够用即可、不是精确参数），若再现"时好时坏"应先看 trace 的 `budgets` 与 `variants` 定位，而不是直接改参数。
