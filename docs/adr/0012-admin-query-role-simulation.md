# 管理员查询角色模拟仅作用于数据访问，并按消息隔离模型历史

管理员需要在同一账号内演示不同角色的知识领域与订单权限，因此 `/api/chat` 增加请求级 `query_role`，取值为现有五类角色。查询角色只传给知识检索与订单工具，不修改登录身份、会话归属或管理员后台权限；非管理员传入该参数时服务端直接拒绝。

每条用户与助手消息记录查询角色。会话记录和界面回放保留同一会话内的全部角色消息，但送给 LLM 的历史只包含相同查询角色的消息；旧消息没有该字段时，仅在查询角色等于账号实际角色时视为有效历史。这样既可以在一个会话中连续切换角色演示，也避免上一角色的答案被下一次模拟引用。

**Considered Options**：按会话锁定查询角色（隔离更强，但每次切换都要新建会话，受每用户 5 个会话上限影响）；只影响当前请求且历史完全不隔离（实现最简，但权限测试可能被上一轮回答污染）；为每次切换自动清空上下文（实现简单，但不能复用同角色的既有对话）。

**Consequences**：查询角色成为消息级审计信息，`messages` 表需要新增可空列；管理员看到的完整会话与模型实际使用的历史范围不同。该能力不是权限授予机制，不能用于让非管理员临时提权，也不能替代服务端接口鉴权。
