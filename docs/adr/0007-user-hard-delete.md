# 账号停用与删除分离，删除前置停用且保留知识文档

账号管理提供两级操作：停用（`is_active=0`，可恢复，用户名仍占用）与永久删除（记录从数据库移除、用户名释放）；删除仅对已停用账号开放（两步防误删），被删账号上传的文档保留、`uploaded_by` 由应用层置空（事务内先 `UPDATE documents SET uploaded_by=NULL` 再删行，因 SQLite 无法为既有表追加 `ON DELETE SET NULL` 外键动作）。本 ADR 修订 ADR 0004 中"删除即停用"的旧语义；API 采用 `PUT /:id/deactivate`、`PUT /:id/activate`、`DELETE /:id`（恢复删除本义），前端为唯一消费方、同步替换无兼容负担。

**Considered Options**：删除可对任意账号一步执行（有手滑风险，且绕过停用环节的"最后一个可用 admin"保护）；有上传文档的账号拒绝删除（把账号生命周期与知识资产耦合，演示与运维都被卡住）；级联删除其上传文档（知识库属公司资产，不应随个人账号消失）；保守叠加 `DELETE /:id/purge` 保留旧语义（永久留下别扭的双 DELETE 接口）。

**Consequences**：删除操作需两步（先停用再删除）；停用中的最后一个可用 admin 保护依然有效（停用环节拦截）；被删用户的 JWT 因用户不存在自动失效；文档列表中不再出现该上传者（本来就不展示该字段）；用户名重建后为新账号，与历史文档无关联。
